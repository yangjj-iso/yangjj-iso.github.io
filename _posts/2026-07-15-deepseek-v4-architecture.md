上下文到了百万 token 的量级，标准注意力机制里「每个 token 都要和前面所有 token 算一遍关系」的做法就很难撑住，算力和显存会一起见顶。DeepSeek V4 给出的结果是：生成下一个 token 的计算量约为上一代的 27%，KV 缓存约为上一代的 10%。这篇文章顺着 V4 的四层架构，看看混合注意力、MHC、MoE 和 MTP 各自要解决什么问题、大致怎么做、带来什么收益。

<!--more-->

V4 没有靠某个单点技巧，它把当下几项主流技术整合进了一套自洽的架构：长文本靠混合注意力跑得动，深层网络里的信息靠 MHC 保持不失真，有限的算力靠 MoE 分配到需要的地方。本文根据一段讲解 DeepSeek V4 底层架构的视频整理并扩写，重点在核心机制，部分实现细节只停留在设计思路层面。

为了让没接触过 Transformer 的读者也能读下去，正文前先补一节预备知识，把后面反复出现的名词讲清楚；熟悉这些概念的可以直接跳到第一章。

## 预备知识

### Token（词元）

模型并不直接读「字」或「词」，它会先把文本切成一小块一小块，每一块叫一个 token。一个 token 可能是一个字、一个词，或半个单词，模型的所有处理都以 token 为单位。所谓「百万级 token 的长文本」，就是切完有上百万个 token 的超长文档。token 越多，要处理的东西越多，开销越大，后面关于省算力的讨论都建立在这一点上。

### Transformer

Transformer 是几乎所有现代大模型（GPT、DeepSeek 等）共用的网络结构，可以看成一摞叠起来的处理层：文本从底层进入，逐层加工，每一层都让模型对这段文字理解得更深一点。深的模型可能有几十甚至上百层。它最核心的部件是注意力机制。

### 注意力机制（Attention）

读「他把它放进了它里面」这句话时，人会联系上下文判断每个「它」指什么。注意力机制让模型做同样的事：处理某个 token 时，去关注句子里其他相关的 token，比如处理「它」时多看一眼前面的名词。

这是 Transformer 最强的能力，也是最耗算力的地方：原则上每个 token 都要和其他所有 token 互相看一遍，token 一多，计算量按平方增长。

### QKV（Query / Key / Value）

注意力具体靠 QKV 来实现。每个 token 会被映射成三个向量：

| 名称 | 含义 | 图书馆比喻 |
| --- | --- | --- |
| Query（查询，Q） | 我现在想找什么信息 | 你心里的搜索问题：「关于唐朝的书在哪？」 |
| Key（键，K） | 我这个 token 能提供什么、是关于什么的 | 每本书的标签 / 索书号 |
| Value（值，V） | 我实际携带的具体内容 | 书里真正的内容 |

计算过程和在图书馆查资料差不多：拿 Query 去和每本书的 Key 比对，得到相关性分数；再按分数把各本书的 Value 加权汇总，相关的多取一点，不相关的少取一点。这样当前 token 就读到了上下文里最相关的信息。Q 负责提问，K 负责被检索，V 负责提供内容。

后面反复出现的 KV 缓存也在这里解释一下：模型逐词生成时，前面每个 token 算出的 K 和 V 会被存起来反复使用，免得每生成一个新词就把前文全部重算一遍。文本越长，缓存越大，越占显存。后面说的「把 KV 缓存压到 10%」指的就是它。

### 残差连接与梯度

- 残差连接（Residual）：网络很深时，信息容易在层层加工中走样。残差的做法是把这一层的输入直接加到这一层的输出上，给信息留一条近路，避免深层网络越学越糊。
- 梯度（Gradient）：训练就是根据「错得多离谱」不断微调参数，「往哪个方向调、调多少」的信号就是梯度。网络太深时，梯度容易爆炸（越传越大、训练失控）或消失（越传越小、深层学不动）。后面的 MHC 要解决的就是这个问题。

### 显存与算力

算力是完成一次计算需要的运算量，决定了快不快、贵不贵；显存（GPU 内存）是显卡上临时存放数据（包括 KV 缓存）的空间，装不下就跑不了。长文本会同时把这两样顶到上限，所以 V4 的很多设计都在做同一件事：在尽量不损失效果的前提下，把算力和显存开销压下来。

## 一、整体架构：四层堆叠

DeepSeek V4 的架构自下而上可以分成四层，每层解决一类问题：

| 层 | 解决的核心问题 | 关键技术 |
| --- | --- | --- |
| 模型架构层 | 怎么把 Transformer 本身做得更高效、更稳 | 混合注意力（CSA + HCA）、MHC 残差、MoE 混合专家 |
| 训练优化层 | 怎么让模型在训练时学到更强的能力 | MTP 多 token 预测 |
| 系统层 | 怎么让训练/推理在真实硬件上跑得快、省 | 显存、KV 缓存、并行调度等工程优化 |
| Agent 层 | 怎么让模型从「会答」走向「会做事」 | 工具调用、规划、执行等 agent 能力 |

这四层互相支撑：模型架构层省下的算力，决定了系统层能不能扛住百万 token；训练层的 MTP 又增强了模型对长文本的理解。下面重点讲最核心的模型架构层和训练优化层。

## 二、混合注意力（CSA + HCA）

标准注意力里，每个 token 都要和前面所有 token 算一遍关系，文本越长，计算量和显存（主要是 KV 缓存）涨得越快。到了百万级 token，这套机制基本扛不住。

V4 的思路是把 token 分组，再压缩每组的 KV 向量，不再让每个 token 都保留完整的 KV 信息，参与计算和缓存的信息量因此大幅下降。它搭配使用两种压缩力度不同的注意力：

- CSA（轻度压缩）：压缩得比较温和，保留较多细节，适合需要精细分辨的局部信息，类似逐句精读。
- HCA（重度压缩）：压缩得很狠，接近给一整段做摘要，适合把握全局大意，类似快速扫一遍全文抓主旨。

一路保细节，一路看全局，开销也压了下来。收益很直接：生成下一个 token 的**计算量约为上一代的 27%**，**KV 缓存约为上一代的 10%**。同样的硬件，能跑更长的上下文、更快地出 token、容纳更多并发请求，V4 处理百万级长文本靠的就是这一点。

## 三、MHC：让信息在深层网络里不被稀释

Transformer 靠残差连接缓解深层网络的梯度问题，但它有个副作用：层数一多，一轮轮累加下来，真正有效的信息会被逐渐稀释，淹没在不断叠加的信号里。到几十上百层时这个问题尤其明显，还容易伴随梯度爆炸或消失。

MHC 不再把输入直接加回去，而是复制输入，再乘以一个可学习的矩阵。这个矩阵有两个约束：元素非负；每一行、每一列之和都为 1（即所谓的双随机 / 守恒矩阵）。两个约束合起来，信息在传递中总量守恒，既不会被无限放大（避免梯度爆炸），也不会被稀释抹平（避免梯度消失和信息丢失）；矩阵可学习，则让模型自己决定哪些信息该往深层多传一点。

打个比方，普通残差像把一杯杯水不断倒进同一个桶，越往后越分不清哪滴是关键的；MHC 则像给每层配了一个按比例分配的阀门。结果是信息在深层稳定传输，梯度更健康，模型可以做得更深、训练更稳。

## 四、MoE 混合专家：把算力用在需要的地方

普通大模型里，每来一个 token，全部参数都要参与计算，既贵又浪费，因为单个 token 用不上那么多「知识」。

MoE（Mixture of Experts，混合专家）的做法是在网络里并排放许多个小网络，每个叫一个「专家」。token 进来后，先由 Router（路由器）给所有专家打分，只挑分数最高的 k 个专家来处理，其余专家这次不参与。这样模型的总参数量可以很大，容纳更多知识，而每个 token 实际激活的只是一小部分，计算量可控，也就是所谓的「大而稀疏」。

只有专家还不够。如果每个专家都要自己掌握通用常识，就会重复学习、互相挤占。V4 额外引入了通识网络（共享专家），统一处理人人都要用的基础知识，各个专家就能卸下这部分负担，专注于自己的细分领域。最终在总知识容量和单次计算成本之间取得了不错的平衡：参数规模上去了，推理成本没有同比例上涨。

## 五、MTP：一次预测多个 token

经典语言模型的训练目标是给定前文，预测紧接着的下一个词（Next-Token Prediction）。这很有效，但有点短视：每一步只盯着眼前一个词，对更长远的走向缺少直接的训练信号。

MTP（Multi-Token Prediction，多 token 预测）让模型在训练时看到一个词后，预测接下来的多个词。要预测好，模型必须对接下来一小段内容的整体走向有把握，而不只是做「下一个字接龙」。这带来三点收益：模型习惯了着眼于更长的跨度，长文本处理能力更强；多步预测要求对内容的逻辑走向建模，推理能力更强；训练信号更丰富，同样的数据能学到更多。

## 六、几项技术怎么配合

回头看，这几项技术是互相咬合的。混合注意力把长文本的计算量和 KV 缓存降到上一代的约 27% 和 10%，让模型「看得起」超长上下文，MTP 则让模型学会用好这些上下文；MHC 让更深的网络训得稳；MoE 加通识网络让参数规模和推理成本脱钩。

再往上，系统层的工程优化负责让这些设计在真实硬件上跑得快、跑得省，Agent 层则把模型能力封装成工具调用、规划和执行，从「会答」走向「会做事」。这两层本文没有展开。
