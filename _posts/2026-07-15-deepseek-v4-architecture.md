## 写在前面

大模型发展到今天，单纯「堆参数、堆数据」已经不够看了。真正拉开差距的，是底层架构上的精巧设计——怎么在百万级长文本下还跑得动、怎么让信息在几十上百层网络里不失真、怎么让有限的算力用在刀刃上。

DeepSeek V4 是这方面一个很好的样本：它不是某一个孤立的trick，而是把当下主流的几项关键技术系统性地整合进了一套自洽的架构里。这篇文章就按它的四层结构，逐层拆开讲。

说明：本文基于一段讲解 DeepSeek V4 底层架构的视频整理并扩写，重在把核心机制讲透，部分实现细节以「设计思路」层面呈现。

## 预备知识：先把几个名词讲明白（看不懂术语就先读这里）

后面会反复出现一串专业词。这一节用最朴素的比喻把它们讲清楚，读完再看正文会顺很多。如果你已经熟悉这些概念，可以直接跳到第一章。

### 0.1 Token（词元）：模型眼里的「文字最小单位」

模型并不直接读「字」或「词」，而是先把文本切成一小块一小块，每一块叫一个 token（词元）。一个 token 可能是一个字、一个词，或半个单词。模型的一切处理都是以 token 为单位进行的。

「百万级 token 的长文本」= 一篇切完有上百万个小块的超长文档。token 越多，要处理的东西就越多，开销也越大——这是后面所有「省算力」讨论的前提。

### 0.2 Transformer：当今大模型的通用骨架

Transformer 是几乎所有现代大模型（GPT、DeepSeek 等）共用的网络结构。你可以把它想成一摞叠起来的「信息处理层」，文本从底层进、一层层往上加工，每一层都让模型对这段文字理解得更深一点。深的模型可能有几十甚至上百层。

它最核心的零件，就是下面要讲的「注意力机制」。

### 0.3 注意力机制（Attention）：让每个词「看看别的词」

读「他把它放进了它里面」这句话时，你的大脑会自动判断每个「它」指代什么——靠的是联系上下文。

注意力机制就是让模型干这件事：处理某个 token 时，让它去「关注」句子里其他相关的 token，从而结合上下文理解自己。比如处理「它」时，注意力会让模型多看一眼前面的名词。

这是 Transformer 最强大的能力，但也是最烧算力的地方——因为原则上每个 token 都要和其他所有 token 互相看一遍，token 一多，计算量就平方级暴涨。

### 0.4 QKV（Query / Key / Value）：注意力到底怎么算出来的

注意力机制具体是怎么实现「让一个词去关注其他词」的？答案就是 QKV 三件套。每个 token 都会被映射成三个向量：

| 名称 | 含义 | 图书馆比喻 |
| --- | --- | --- |
| Query（查询，Q） | 我现在想找什么信息 | 你心里的搜索问题：「关于唐朝的书在哪？」 |
| Key（键，K） | 我这个 token 能提供什么、是关于什么的 | 每本书的标签 / 索书号 |
| Value（值，V） | 我实际携带的具体内容 | 书里真正的内容 |

注意力的计算过程，就像在图书馆查资料：

- 拿你的 Query 去和每本书的 Key 比对，算出「这本书和我的问题有多相关」（相关性打分）；
- 越相关的书，分数越高；
- 按这个分数，把各本书的 Value（内容）加权汇总起来——相关的多拿一点，不相关的少拿一点。

这样，当前 token 就「读」到了上下文里最相关的信息。这就是 QKV 的作用：Q 负责提问，K 负责被检索，V 负责提供内容。

顺带解释一个后面反复出现的词——KV 缓存：模型在逐词生成时，前面每个 token 算出的 K 和 V 会被存起来反复使用，免得每生成一个新词就把前文全部重算一遍。文本越长，这个缓存越大、越吃显存。后面「把 KV 缓存压到 10%」说的就是它。

### 0.5 残差连接、梯度：让深层网络训得动

- 残差连接（Residual）：网络很深时，信息容易在层层加工中走样。残差的做法是把「这一层的输入」直接抄一份加到「这一层的输出」上，相当于给信息留了一条抄近道的高速公路，避免深层网络越学越糊。
- 梯度（Gradient）：训练就是不断根据「错得多离谱」去微调参数，这个「该往哪个方向调、调多少」的信号就是梯度。网络太深时，梯度容易爆炸（越传越大、训练失控）或消失（越传越小、深层学不动）。后面 MHC 机制要解决的正是这个问题。

### 0.6 显存与算力：为什么大家拼命「省」

- 算力：完成一次计算需要的运算量，直接决定快不快、贵不贵；
- 显存（GPU 内存）：显卡里临时存放数据（含 KV 缓存）的空间，装不下就跑不了。

长文本会同时把算力和显存顶到天花板。所以你会看到 V4 反复在做同一件事：在尽量不损失效果的前提下，把算力和显存的开销压下来。

读懂了以上这些，下面的正文就都能跟上了。

## 一、整体架构：四层堆叠

DeepSeek V4 的架构可以自下而上分成四层，每一层解决一类问题：

| 层 | 解决的核心问题 | 关键技术 |
| --- | --- | --- |
| 模型架构层 | 怎么把 Transformer 本身做得更高效、更稳 | 混合注意力（CSA + HCA）、MHC 残差、MoE 混合专家 |
| 训练优化层 | 怎么让模型在训练时学到更强的能力 | MTP 多 token 预测 |
| 系统层 | 怎么让训练/推理在真实硬件上跑得快、省 | 显存、KV 缓存、并行调度等工程优化 |
| Agent 层 | 怎么让模型从「会答」走向「会做事」 | 工具调用、规划、执行等 agent 能力 |

这四层不是各自为政，而是层层支撑：模型架构层的省算力设计，直接决定了系统层能不能扛住百万 token；训练层的 MTP 又反过来增强了模型对长文本的理解。下面我们重点拆解最核心的模型架构层和训练优化层。

## 二、混合注意力机制（CSA + HCA）：让百万 token 不再「算到爆」

### 2.1 问题：注意力的代价随长度暴涨

标准 Transformer 的注意力机制有个老毛病：每个 token 都要和前面所有 token 算一遍关系。 文本越长，计算量和显存（主要是 KV 缓存）增长得越凶。当上下文来到百万级 token 时，这套机制几乎扛不住——算力和显存双双爆炸。

KV 缓存是什么？简单说，模型在生成时会把每个历史 token 的「Key/Value 向量」存下来反复用，避免重算。文本越长，这个缓存越大，显存压力越重。

### 2.2 解法：分组 + 压缩 KV 向量

DeepSeek V4 的思路是：与其让每个 token 都保留完整的 KV 信息，不如把 token 分组，再把每组的 KV 向量压缩。 这样需要参与计算和缓存的信息量就大幅下降。

它用了两种压缩力度不同的注意力，搭配使用：

- CSA（轻度压缩）：压缩得比较温和，保留较多细节。适合需要精细分辨的局部信息——好比读一段话时逐句精读。
- HCA（重度压缩）：压缩得很狠，类似给一整段做摘要。适合把握全局大意，而不纠结每个字——好比快速扫一遍全文抓主旨。

一精一粗两路配合，既能抓住关键细节，又能纵览全局，还把开销压了下来。

### 2.3 收益：算力降到 27%，KV 缓存降到 10%

这套混合注意力带来的收益非常直接：

- 生成下一个 token 的**计算量仅为上一代的约 27%**；
- **KV 缓存仅为上一代的约 10%**。

也就是说，同样的硬件，能跑更长的上下文、更快地出 token、塞下更多并发请求。这是 V4 能从容处理百万级长文本的根基。

## 三、MHC 机制：让信息在深层网络里「不被稀释」

### 3.1 问题：残差连接的副作用——有效信息被稀释

Transformer 靠残差连接（把每一层的输入直接加到输出上）来缓解深层网络的梯度问题。但它有个副作用：层数一多，一轮轮地「加来加去」，真正有效的信息会被逐渐稀释，淹没在不断累加的信号里。深到几十上百层时，这个问题尤其明显，还容易伴随梯度爆炸或消失。

### 3.2 解法：用一个「守恒」的矩阵稳定信息传输

MHC 的做法是：不再简单粗暴地把输入直接加回去，而是复制输入，并乘以一个可学习的矩阵。这个矩阵有两个关键约束：

- 元素非负；
- 每一行、每一列之和都为 1（即所谓的双随机 / 守恒矩阵）。

这两个约束合在一起，意味着信息在传递过程中总量被「守恒」住了——既不会被无限放大（避免梯度爆炸），也不会被稀释抹平（避免梯度消失/信息丢失）。可学习则保证模型能自己决定「哪些信息该往深层多传一点」。

打个比方：普通残差像是把一杯杯水不断倒进同一个桶里，越往后越分不清哪滴是关键的；MHC 则像给每层配了一个「定量、按比例分配」的阀门，让关键信息能稳稳地流到网络深处。

### 3.3 收益

信息在深层网络中稳定传输，梯度更健康，模型可以做得更深、训练更稳，深层表达能力得以释放。

## 四、混合专家系统（MoE）：把算力用在刀刃上

### 4.1 思路：不是每个 token 都劳动全部参数

普通大模型里，每来一个 token，整个网络的全部参数都要参与计算——既贵又浪费，因为一个 token 其实用不上那么多「知识」。

MoE（Mixture of Experts，混合专家）换了个思路：

- 网络里并排放着许多个小网络，每个叫一个「专家」；
- 每个 token 进来后，先由一个 Router（路由器） 给所有专家打分；
- 只挑分数最高的 k 个专家来处理这个 token，其余专家这次不参与。

这样一来，模型的总参数量可以非常大（容纳海量知识），但每个 token 实际激活的参数只是一小部分（计算量可控）。这就是「大而稀疏」的精髓。

### 4.2 通识网络：让专家更专精

只有专家还不够。如果每个专家都得自己掌握「通用常识」，就会重复学习、互相挤占。V4 额外引入了通识网络（共享专家）：

- 通用、人人都要用的基础知识，交给通识网络统一处理；
- 各个专家因此可以卸下通用包袱，专注于自己擅长的细分领域，变得更专精。

好比一个团队：基础杂务有公共后勤统一负责，每个专家就能心无旁骛地深耕自己的专业。

### 4.3 收益

在「总知识容量」和「单次计算成本」之间取得了很好的平衡——参数规模上去了，推理成本却没有同比例上涨。

## 五、MTP 训练创新：一次看一个词，不如一次预判一串趋势

### 5.1 传统训练：只预测「下一个词」

经典语言模型的训练目标很朴素：给定前文，预测紧接着的那一个词（Next-Token Prediction）。这当然有效，但它有点「短视」——模型每一步只盯着眼前一个词，对更长远的走向缺乏直接的训练信号。

### 5.2 MTP：一次预测后续多个词

MTP（Multi-Token Prediction，多 token 预测）改进了这一点：训练时，让模型看到一个词后，去预测后面接下来的多个词，而不只是下一个。

这相当于逼着模型在每一步都去学习多步的趋势和结构，而不是只做「下一个字接龙」。它必须对接下来一小段内容的整体走向有把握，才能预测得好。

### 5.3 收益

- 更强的长文本处理能力：模型习惯了着眼于更长的跨度；
- 更强的推理能力：多步预测天然要求模型对内容的逻辑走向建模，而不只是表层接龙；
- 训练信号更丰富，同样的数据能学到更多。

值得一提的是，MTP 与第二章的混合注意力是相辅相成的：注意力机制让模型「能看得起」超长上下文，MTP 则让模型「学会用好」这些长上下文。

## 六、总结：四层之间的相互成就

把整篇串起来，DeepSeek V4 的精妙不在于某一个单点技术，而在于它们彼此咬合：

- 混合注意力（CSA + HCA） 把长文本的算力（27%）和 KV 缓存（10%）打下来，奠定「长且快」的基础；
- MHC 残差 用「守恒矩阵」让信息在深层网络稳定传输，撑起「深且稳」；
- MoE + 通识网络 让模型「大而不贵」，参数规模与推理成本解耦，专家各司其职；
- MTP 训练 让模型从「下一个词」升级到「多步趋势」，强化长文本与推理能力；
- 这一切再被系统层的工程优化和Agent 层的能力封装，最终从「会答」走向「会做事」。

一句话概括：V4 不是靠某个绝招取胜，而是把「又长、又快、又稳、又准、又省」这几件原本互相冲突的事，用一套分层架构同时做到了一个不错的平衡点。 这也正是当下大模型架构演进的主旋律——从单点突破，走向系统级整合。
